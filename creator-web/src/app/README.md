# 앱 실행 구조

`index.html`의 일반 스크립트 태그(`/app.js`)는 기존 큰 인라인 스크립트와 같은 위치에서 실행됩니다. `type="module"`, `async`, `defer`를 붙이지 않아 기존 버튼의 전역 함수 연결과 DOM 준비 순서를 유지합니다.

| 파일 | 역할 |
|---|---|
| `runtime-manifest.js` | 기능별 일반 JS 조립 목록: 상태 → 기능 함수 → 시작 코드 |
| `bootstrap.js` | 편집 상태·이벤트 연결·화면 복원·초기 조회의 시작 순서 |
| `data-sync.js` | 여러 기능의 서버 조회를 함께 수행하고 각 기능의 화면 갱신 함수 호출 |
| `main.js` | 기존 ES 모듈의 데이터 서비스·오류 처리·프로필 필드를 window에 연결 |
| `../../build/classicRuntime.js` | 개발 서버 `/app.js` 제공, 빌드 자산 생성, 자동 새로고침·소스맵 처리 |

일반 JS 파일은 독립 ES 모듈이 아닙니다. 함수 선언과 상태가 한 실행 범위를 공유합니다. `state.js`는 해당 상태의 선언 위치이며, 기능 간 접근을 차단하는 캡슐화까지 도입한 것은 아닙니다. 기존 `onclick`과 `window` 연동을 유지하기 위한 구성입니다.

인증·온보딩·약관·데이터 서비스처럼 이미 ES 모듈이었던 파일은 기존 `import`/`export` 방식을 유지합니다. `main.js`가 데이터 서비스를 먼저 import한 뒤 전역에 연결하고 인증 모듈이 이어집니다. 중복 데이터 서비스 script 태그는 제거했습니다. 일반 JS 조립 목록에 이 ES 모듈들을 추가하지 않습니다.

배포 파일은 자동 생성되는 `dist/assets/app-[내용 해시].js` 한 개와 소스맵입니다. 개발자 도구에서는 소스맵으로 원래 기능 파일을 찾을 수 있습니다. 임시 `legacy.js`는 제거했으며 별도의 수동 복사 작업은 필요하지 않습니다.
