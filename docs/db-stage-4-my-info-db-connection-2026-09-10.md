## 실DB 검증 결과

- `support_tickets`: RLS 활성, 정책 2개, 테스트 종료 후 행 0건
- 비로그인 역할: 고객센터 SELECT 불가, private profile RPC 실행 불가
- 로그인 역할: 허용된 문의 입력 컬럼에만 INSERT 가능
- 본인 프로필 RPC: 조회 1행·수정 1행, 모두 `auth.uid()` 소유 행만 반환
- 고객센터 RLS: 본인 문의 1행만 조회, 다른 사용자 테스트 문의 0행 노출
- SNS 링크: 전체 사용자 6행 모두 배열, 비배열 0행
- 인덱스 3개 생성 확인

검증용 프로필 수정과 문의 데이터는 하나의 트랜잭션에서 실행한 뒤 `ROLLBACK`했으므로 실제 사용자 데이터에는 남지 않았다.

## 보안·성능 어드바이저 메모

- 본인 개인정보만 반환하도록 설계한 두 RPC가 `SECURITY DEFINER`이므로 구조상 경고가 표시된다. 두 함수 모두 `authenticated`에만 실행 권한을 주고 내부에서 `auth.uid()`를 고정해 다른 사용자 ID를 입력받지 않는다. 역할 기반 교차 사용자 검증도 통과했다.
- 기존 Auth 설정의 유출 비밀번호 보호 기능은 아직 비활성화 상태다. DB 4단계 로직 오류는 아니며 Supabase Auth 설정에서 별도 활성화할 항목이다.
- 남은 미인덱스 FK 7개와 private 백업 테이블 PK 안내 6개는 기존 어드바이저 항목이다. 이번 화면의 최신순 조회 경로 3개에는 인덱스를 추가했다.

## 최종 수동 확인

실제 계정으로 `localhost:3000`에 로그인한 뒤 아래 UX 스모크 테스트만 수행하면 된다.

1. 프로필 수정 모달을 열어 이메일과 기존 값이 본인 정보인지 확인한다.
2. 관심분야 또는 소개를 저장하고 새로고침 후 유지되는지 확인한다.
3. 내 프로젝트의 등록·참여·스크랩 탭이 각자 올바른 목록을 표시하는지 확인한다.
4. 돼지코인내역이 실제 잔액과 일치하는지 확인한다.
5. 고객센터에 테스트 문의를 등록하고 내 문의 목록에 즉시 나타나는지 확인한다.
