## 모델링 판단

- `category`와 `is_ab_test`는 독립 속성으로 유지했다. 투표도 A/B 방식이 될 수 있기 때문이다.
- 기존 A/B 시드 2건은 전용 A/B URL 대신 공통 서비스 URL을 사용한다. 현재 실행 흐름이 공통 URL을 안전한 대체 경로로 사용하므로 전용 URL을 억지로 생성하지 않았다.
- 프로덕트·프로토타입은 서비스 또는 앱 실행 주소가 필요하지만, 내부 투표·직접 설문은 URL 없이도 가능하도록 구분했다.
- 화면의 “대분류 생략”은 DB에 의미 없는 `none`을 저장하지 않고 내부 설문을 뜻하는 `survey`로 변환한다.
- 리뷰 테이블의 `project_id`, `user_id`는 조회 편의를 위해 유지하되 참여 행과 다르게 저장될 수 없도록 복합 외래 키를 추가했다.
- `total_funded_cost`가 `reward_coin × target_count`보다 작은 기존 프로젝트 3건은 시드/요금 정책 차이일 수 있어 이번 제약에서 제외했다. 실제 프로젝트 결제 트랜잭션을 만들 때 별도 정책으로 확정해야 한다.

## 회귀 테스트

새 제약이 5단계 트랜잭션을 막지 않는지 하나의 롤백 트랜잭션에서 재검증했다.

1. 프로젝트 참여 성공
2. 리뷰 저장과 참여 상태 `submitted` 전환 성공
3. 서버 기준 100동전 지급 성공
4. 1,200동전 상품 교환 성공
5. 테스트 종료 후 전체 `ROLLBACK`

롤백 후 운영 DB는 프로젝트 9건, 참여·리뷰·코인 거래·교환 0건으로 테스트 전과 같다.

## Advisor 및 7단계 전달 사항

- Security Advisor의 `SECURITY DEFINER` 5건은 사용자 본인 확인과 원자적 거래를 위한 기존 의도된 RPC다. 비로그인 권한 제거와 역할 기반 검증을 완료했다.
- 유출 비밀번호 보호 비활성 경고 1건은 Auth 대시보드 설정으로 남아 있다.
- Performance Advisor가 표시한 실제 public 미인덱스 FK는 3개다.
  - `notifications.user_id`
  - `scraps.project_id`
  - `reviews(participation_id, project_id, user_id)`
- 위 3개는 7단계 조회 쿼리·인덱스 최적화에서 처리한다.
- 데이터가 아직 없는 테이블의 새 인덱스는 사용 통계가 0이라 미사용으로 표시된다. 운영 쿼리 검토 없이 삭제하지 않는다.
